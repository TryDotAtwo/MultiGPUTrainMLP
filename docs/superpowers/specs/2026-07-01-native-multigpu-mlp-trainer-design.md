# Архитектура Нативного Многокарточного Тренера МЛП

## Цель

Построить нативный тренер МЛП для обучения оценочной модели под уже существующий быстрый инференс в проекте `D:\100XH100`. Тренер должен работать на одной видеокарте, проходить первый внешний прогон на Кагле с двумя Т4, затем запускаться на восьми А100 на кластере и масштабироваться дальше до многосерверных запусков.

Главное ограничение: обучение строится под формат быстрого инференса, а не под удобный формат Пайторча. Пайторч допускается только как эталон для малых проверок и численного сравнения.

## Контекст

Входной пример из архива обучает модель расстояния до цели:

```text
group_id = 888
target_id = 0
state_len = 72
move_count = 18
output_dim = 1
K_min = 1
K_max = 29
hd1 = 2556
hd2 = 218
nrd = 16
batch_size = 100000
```

Проект поиска уже содержит быстрый путь инференса с явным контрактом:

```text
logical_state_len = 72
physical_state_len = 80
state_alignment = 16
move_count = 18
output_dim = 1
```

Для состояния действует правило:

```text
State.v[0..71]  = логическое состояние
State.v[72..79] = служебная зона / выравнивание
```

В постоянных состояниях служебная зона равна нулю. В таблице ходов позиции `72..79` отображаются сами в себя.

## Выбранный Подход

Выбран самостоятельный нативный тренер.

Разделение ответственности:

```text
Раст:
    командная строка
    проверка конфигурации
    каталоги запусков
    журналы
    описание контрольных точек
    запуск профилей и переборов

Си++:
    запуск ранга
    подготовка устройств
    подготовка межкарточной связи
    расчет плана памяти
    чтение и запись артефактов

КУДА + КАТЛАСС:
    генерация случайных блужданий
    прямой проход
    обратный проход
    градиенты
    шаг АдамВ
    повторяемые шаблоны запусков

эн-си-си-эл:
    сведение градиентов между рангами
```

Горячий путь не использует Пайторч, не использует общий набор данных на диске и не выделяет память внутри цикла обучения.

## Модель

Модель версии один:

```text
вход:
    State[пачка]

слой ввода:
    таблица позиция-значение
    размер: state_len * num_classes -> hd1

нормализация:
    пакетная нормализация, сворачиваемая в веса для инференса

скрытый слой:
    hd1 -> hd2

остаточные блоки:
    nrd блоков
    каждый блок: hd2 -> hd2 -> hd2

выход:
    hd2 -> 1
```

Тренер пишет веса в формате, который читает быстрый инференс. Отдельный формат разрешен только для состояния оптимизатора и полного возобновления обучения.


## Память

Постоянная память устройства:

```text
generators[MOVE_COUNT][STATE_STORAGE_LEN] : uint8_t
target_state[STATE_STORAGE_LEN]           : uint8_t
```

Постоянная видеопамять ранга:

```text
model_weights
optimizer_m
optimizer_v
gradient_buffers
random_state
training_scratch
communication_buffers
```

Временный буфер `training_scratch` имеет фазовые раскладки:

```text
layout_generate:
    states[BATCH_STATES_PER_RANK] : TrainState80
    labels[BATCH_STATES_PER_RANK] : float
    walk_meta[BATCH_STATES_PER_RANK] : WalkMeta

layout_forward:
    активации_первого_слоя[BATCH_STATES_PER_RANK][HD1]
    активации_второго_слоя[BATCH_STATES_PER_RANK][HD2]
    активации_остаточных_блоков[RESIDUAL_ACTIVE_SLOTS][BATCH_STATES_PER_RANK][HD2]
    выход[BATCH_STATES_PER_RANK]

layout_backward:
    градиент_выхода[BATCH_STATES_PER_RANK]
    градиент_скрытого_слоя[BATCH_STATES_PER_RANK][HD2]
    градиент_остаточного_блока[BATCH_STATES_PER_RANK][HD2]
    фиксированный_буфер_редукций

layout_allreduce:
    буфер_отправки_градиентов
    буфер_приема_градиентов
    смещения_градиентов[PARAM_BLOCK_COUNT + 1]

layout_checkpoint:
    буфер_подготовки_экспорта
    буфер_контрольных_сумм
```

Инвариант наложения:

```text
layout_generate, layout_forward, layout_backward, layout_allreduce, layout_checkpoint
используют одну физическую область training_scratch.

Фазы не активны одновременно, если их области наложены.

Модель, градиенты, состояние оптимизатора, таблица ходов и состояние генератора
не входят в training_scratch.

training_scratch_bytes =
    max(
        layout_generate_bytes,
        layout_forward_bytes,
        layout_backward_bytes,
        layout_allreduce_bytes,
        layout_checkpoint_bytes
    )
```

Первый корректный вариант допускает раздельные области внутри `training_scratch`. После профилирования разрешено сжимать память через наложение фаз, если времена жизни буферов явно доказаны.

## Фазы Выполнения

### Подготовка

```text
загрузить описание группы
загрузить целевое состояние
проверить размеры и выравнивание
рассчитать емкости
выделить память
подготовить повторяемые шаблоны запусков
обнулить счетчики
```

### Генерация

Каждый ранг сам генерирует случайные блуждания от целевого состояния.

Сид:

```text
seed = hash(BASE_SEED, EPOCH, STEP, GLOBAL_RANK)
```

Правила:

```text
общего набора данных на диске нет
немедленный обратный ход запрещен
служебная зона состояния после генерации равна нулю
метка равна длине блуждания
```

### Прямой Проход

```text
состояния -> таблица позиция-значение -> hd1 -> hd2 -> остаточные блоки -> выход
```

Промежуточные активации сохраняются только если они нужны обратному проходу. Полный входной разреженный вектор не материализуется.

### Потери И Обратный Проход

```text
ошибка = средняя квадратичная ошибка
```

Градиент первого слоя собирается по индексам состояния. Полная матрица входа не создается.

### Сведение

Если `WORLD_SIZE == 1`, фаза сведения пропускается.

Если `WORLD_SIZE > 1`:

```text
каждый ранг участвует в одинаковом порядке
сводятся только градиенты
состояния и случайные блуждания не пересылаются
после сведения каждый ранг имеет одинаковые градиенты
```

### Шаг АдамВ

```text
weight_decay = 0 по умолчанию
```

Обновление выполняется на видеокарте. Состояния оптимизатора живут в постоянной видеопамяти ранга.

### Контрольная Точка

Быстрая контрольная точка:

```text
manifest.json
веса для быстрого инференса
```

Полная контрольная точка:

```text
manifest.json
веса для быстрого инференса
optimizer_m
optimizer_v
эпоха
шаг
base_seed
снимок конфигурации
```

Запись выполняет главный ранг. Остальные ранги синхронизируются на границе записи.

```text

формат состояния

формат контрольной точки

```

### Малые Численные Проверки

```text
генерация случайных блужданий против эталона
прямой проход против эталона
обратный проход численной проверкой на малой модели
```

### Контейнер На Одной Видеокарте

```text

проверка записи весов

профилировщик

```

Двухкарточный контейнерный этап отсутствует.

### Кагл На Двух Т4

```text
сборка без ручных правок
запуск двух рангов
проверка порядка сведений
проверка совпадения весов после шага
экспорт весов
проверка чтения весов быстрым инференсом
сохранение журналов и артефактов
```

### Восемь А100 На Кластере

```text
тот же код

проверка межкарточного сведения
контрольные точки на общий диск только с главного ранга
возобновление из полной контрольной точки
```

### Многосерверный Запуск

```text
явные параметры главного узла
явный номер узла
журналы по каждому рангу
сводка от главного ранга
проверка одинакового порядка коллективных операций
```

## Инварианты

```text
Внутри шага обучения нет выделения памяти.

Горячий путь не использует Пайторч.

Горячий путь не читает большие буферы на процессор.

Каждый ранг генерирует свои случайные блуждания.

Общий набор данных на диске отсутствует.

Состояния хранятся как 72 логических байта плюс 8 служебных байтов.

Служебные байты постоянных состояний равны нулю.

Таблица ходов имеет физическую ширину 80.

Порядок межкарточных операций одинаков на всех рангах.

Однокарточный запуск использует тот же код, что многокарточный.

Весовой артефакт версии один читается быстрым инференсом поиска без изменения его контракта.

Изменение контракта быстрого инференса не входит в версию один.

Двухкарточная внешняя проверка начинается на Кагле, не в контейнере.
```

## Готовность Версии Один

Версия один считается готовой, когда выполнены все пункты:

```text
однокарточный нативный тренер проходит контейнерный прогон
ошибка на короткой тренировке убывает
численные проверки прямого и обратного прохода проходят
АдамВ проверен на фиксированном примере
веса экспортируются в формат быстрого инференса
быстрый инференс читает экспортированные веса
Кагл на двух Т4 проходит короткий запуск
восьмикарточный запуск на А100 имеет подтвержденное сведение градиентов
внутри цикла обучения нет выделения памяти
```
